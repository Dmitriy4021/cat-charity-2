# QRKot

QRKot — REST API для благотворительного фонда поддержки котиков. Сервис позволяет создавать целевые проекты для сбора пожертвований, принимать пожертвования от зарегистрированных пользователей и автоматически распределять поступившие средства между открытыми проектами. QRKot также поддерживает регистрацию и аутентификацию пользователей, разграничение прав доступа и просмотр истории собственных пожертвований.

## Возможности

- Создание, просмотр, редактирование и удаление благотворительных проектов с учётом прав доступа.
- Регистрация и аутентификация пользователей с использованием FastAPI Users и JWT.
- Создание пожертвований авторизованными пользователями и привязка каждого пожертвования к его автору.
- Просмотр пользователями собственных пожертвований и просмотр всех пожертвований суперпользователем.
- Автоматическое распределение пожертвований между открытыми проектами в порядке их создания.
- Перенос остатка пожертвования на следующий открытый проект.
- Автоматическое закрытие полностью профинансированных проектов и полностью распределённых пожертвований.
- Автоматическое распределение свободных пожертвований при создании нового проекта.
- Валидация входных данных и контроль допустимых операций.
- Асинхронная работа с базой данных.
- API-документация Swagger и ReDoc.

## Установка

```bash
git clone <URL_репозитория>
cd cat-charity-2
```

```bash
python3 -m venv venv
```

## Настройка переменных окружения

Создайте в корне проекта файл .env.

Для SQLite с асинхронным драйвером aiosqlite укажите строку подключения, соответствующую конфигурации проекта:

```text
DATABASE_URL=sqlite+aiosqlite:///./cat_charity.db
```

Для автоматического создания суперпользователя при запуске приложения добавьте следующие переменные окружения:

```text
FIRST_SUPERUSER_EMAIL=admin@example.com
FIRST_SUPERUSER_PASSWORD=your_secure_password
```

Замените admin@example.com на нужный адрес электронной почты, а your_secure_password — на надёжный пароль.

При запуске приложения суперпользователь создаётся с указанными учётными данными, если соответствующая логика реализована в приложении.


Создайте секретный ключ для генерации и проверки токенов аутентификации:

```text
SECRET=your_secret_key
```


## Работа с базой данных

Для управления структурой базы данных используется Alembic.

Применение миграций:

```bash

```

```bash
alembic revision --autogenerate -m "описание изменений"
```

Откат последней миграции:

```bash
alembic downgrade -1
```

В проекте используются три основные модели: CharityProject, Donation и User.

## Пользователи и аутентификация

Для регистрации и аутентификации используется библиотека FastAPI Users. Для идентификаторов пользователей применяется тип int, а для аутентификации — Bearer-токены на основе JWT.

Для доступа к защищённым операциям клиент должен передавать токен в заголовке запроса:

```text
Authorization: Bearer <JWT-токен>
```

Удаление пользователей через API отключено.

## Права доступа

### Анонимный пользователь

Может:

- просматривать список благотворительных проектов, включая открытые и закрытые;
- регистрироваться в системе.

Не может создавать пожертвования и выполнять административные операции.

### Зарегистрированный пользователь

Может:

- просматривать список благотворительных проектов;
- создавать пожертвования;
- просматривать собственные пожертвования.

При просмотре собственных пожертвований пользователь получает только следующие поля:

- id — идентификатор пожертвования;
- comment — комментарий;
- full_amount — сумма пожертвования;
- create_date — дата создания.

Информация о распределении средств и дате закрытия пожертвования обычному пользователю не предоставляется.

### Суперпользователь

Обладает правами зарегистрированного пользователя и дополнительно может:

- создавать благотворительные проекты;
- изменять название и описание проектов;
- изменять целевую сумму проекта при условии, что она не меньше уже инвестированной суммы;
- удалять проекты, в которые ещё не поступали средства;
- просматривать все пожертвования со всеми полями модели.

### Ограничения

Независимо от уровня доступа запрещено:

- удалять пользователей через API;
- редактировать и удалять пожертвования;
- редактировать и удалять закрытые проекты;
- удалять проекты, в которые уже инвестированы средства;
- изменять даты создания и закрытия проектов.

## Благотворительные проекты

Модель CharityProject хранит информацию о целевых сборах.

Основные поля:

- id — идентификатор проекта;
- name — название проекта;
- description — описание;
- full_amount — необходимая сумма;
- invested_amount — уже инвестированная сумма;
- fully_invested — признак полного финансирования;
- create_date — дата создания;
- close_date — дата полного финансирования.

### Получение списка проектов

```text
GET /charity_project/
```

Метод возвращает список проектов, в том числе открытых и закрытых.

### Создание проекта

```text
POST /charity_project/
```

Доступно суперпользователю.

Пример запроса:

```json
{
"name": "Помощь приюту",
"description": "Сбор средств на содержание животных в приюте.",
"full_amount": 100000
}
```

При создании проекта автоматически устанавливаются дата создания, первоначальная сумма инвестиций и статус финансирования. Если имеются свободные пожертвования, они направляются на новый проект в соответствии с логикой инвестирования.

### Редактирование проекта

```text
PATCH /charity_project/{project_id}
```

Доступно суперпользователю.

Можно изменить название, описание и целевую сумму проекта с учётом ограничений. Закрытые проекты редактировать нельзя.

### Удаление проекта

```text
DELETE /charity_project/{project_id}
```

Доступно суперпользователю только для проектов, в которые ещё не поступали средства.

## Пожертвования

Модель Donation хранит информацию о пожертвовании и его авторе.

Основные поля:

- id — идентификатор пожертвования;
- user_id — идентификатор пользователя, создавшего пожертвование;
- comment — комментарий;
- full_amount — сумма пожертвования;
- invested_amount — распределённая сумма;
- fully_invested — признак полного распределения;
- create_date — дата создания;
- close_date — дата полного распределения.

### Создание пожертвования

```text
POST /donation/
```

Создавать пожертвования могут только авторизованные пользователи.

Пример запроса:

```json
{
"full_amount": 5000,
"comment": "Желаю помочь приюту."
}
```

Автор пожертвования определяется автоматически по текущему аутентифицированному пользователю.

### Просмотр собственных пожертвований

Зарегистрированный пользователь может получить список своих пожертвований. В ответе доступны только поля id, comment, full_amount и create_date.

### Просмотр всех пожертвований

Суперпользователь может получить список всех пожертвований с полной информацией, включая данные о распределении средств.

Редактирование и удаление пожертвований через API не допускаются.

## Автоматическое инвестирование

Пожертвования автоматически распределяются между открытыми проектами в порядке их создания. Средства сначала направляются на самый старый проект, который ещё не получил необходимую сумму.

Например, если первому проекту требуется 5 000, второму — 10 000, а поступившее пожертвование составляет 15 000, оба проекта могут быть полностью профинансированы.

Если суммы пожертвования недостаточно для завершения проекта, средства инвестируются частично. После завершения одного проекта остаток направляется следующему открытому проекту.

Если на момент создания пожертвования открытых проектов нет, средства остаются нераспределёнными. При создании нового проекта свободные пожертвования могут быть направлены на его финансирование.

При достижении необходимой суммы проект закрывается: fully_invested устанавливается в true, а close_date получает текущую дату и время. Аналогично обновляется состояние полностью распределённого пожертвования.

## Валидация данных

Проект проверяет:

- уникальность названий благотворительных проектов;
- допустимую длину названия проекта;
- минимальную длину описания;
- положительное значение целевой суммы проекта;
- положительное значение суммы пожертвования;
- невозможность уменьшения целевой суммы ниже уже инвестированной;
- невозможность редактирования закрытого проекта;
- возможность удаления только проектов без инвестированных средств;
- корректность идентификаторов и передаваемых данных;
- наличие аутентификации для защищённых операций;
- доступ пользователя только к собственным пожертвованиям при получении личного списка.

## Архитектура

Приложение разделено на несколько уровней:

- api — маршрутизация запросов и валидация API;
- core — конфигурация, подключение к базе данных и настройка пользователей;
- crud — операции с базой данных;
- models — модели SQLAlchemy;
- schemas — схемы Pydantic для валидации и сериализации;
- services — бизнес-логика автоматического инвестирования.

Для асинхронной работы с базой данных используется AsyncSession, а зависимости передаются через механизм Dependency Injection FastAPI.
